数据库设计

新增表结构与字段字典

本次新增 4 张表，复用通知表并扩展通知类型。以下为迁移后的实际字段；时间类型统一为 TIMESTAMP(3)。

UserLocationSettingUserLocationFriendRequestFriendshipNotification

UserLocationSetting · 定位设置

每位用户一条，保存定位开关与被发现设置。

字段 数据库类型 可空 默认值 / 约束 字段说明
userId TEXT 否 主键；外键 → User.id 所属用户；删除用户时级联删除
locationEnabled BOOLEAN 否 false 是否开启定位
discoverable BOOLEAN 否 false 是否允许附近的人发现自己；为 true 时必须开启定位
createdAt TIMESTAMP(3) 否 数据库当前时间 设置创建时间
updatedAt TIMESTAMP(3) 否 Prisma 自动维护 最近设置更新时间

UserLocation · 当前位置

每位用户最多一条，覆盖更新；不保存地址文字和历史轨迹。

字段 数据库类型 可空 默认值 / 约束 字段说明
userId TEXT 否 主键；外键 → User.id 所属用户；删除用户时级联删除
latitude DOUBLE PRECISION 否 −90 ～ 90 纬度，单位为度
longitude DOUBLE PRECISION 否 −180 ～ 180 经度，单位为度
accuracyMeters DOUBLE PRECISION 否 > 0 且 ≤ 100000 系统返回的定位精度，单位为米；附近搜索另按配置筛选
position geography(Point,4326) 生成列 经纬度自动生成；GiST 索引 PostGIS 空间点，用于按米计算距离；无需客户端写入
capturedAt TIMESTAMP(3) 否 客户端采集时间 本次坐标的采集时间
receivedAt TIMESTAMP(3) 否 数据库当前时间；上报时更新 服务端接收本次位置的时间
expiresAt TIMESTAMP(3) 否 capturedAt + 位置有效期 位置失效时间，默认采集后 6 小时

FriendRequest · 好友申请

保存双方申请及处理历史；申请表不再存 userLowId / userHighId。

字段 数据库类型 可空 默认值 / 约束 字段说明
id TEXT 否 主键；Prisma 生成 CUID 申请记录 ID
requesterId TEXT 否 外键 → User.id 发起申请的用户；删除用户时级联删除
recipientId TEXT 否 外键 → User.id；不能等于 requesterId 接收申请的用户；删除用户时级联删除
status FriendRequestStatus 否 PENDING 申请状态，见下方枚举表
requestedAt TIMESTAMP(3) 否 数据库当前时间；创建时写入 发起申请的时间，用于排序
expiresAt TIMESTAMP(3) 否 必须晚于 requestedAt 申请有效期截止时间，默认发起后 7 天
resolvedAt TIMESTAMP(3) 是 PENDING 时为 NULL；其他状态非空 处理时间；拒绝后以此计算默认 24 小时冷静期；落库过期时记录 expiresAt
updatedAt TIMESTAMP(3) 否 Prisma 自动维护 申请记录最近更新时间

好友申请状态 · FriendRequestStatus

值 含义 / 行为
PENDING 待处理；未过期时接收人可同意或拒绝，发起人可撤回
ACCEPTED 已通过，生成好友关系；后续删除好友不改变该申请状态
REJECTED 已拒绝；当前时间早于 resolvedAt + 冷静期时，不可再次申请
CANCELLED 发起人已撤回，无冷静期
EXPIRED 已过期，无冷静期；超时的 PENDING 记录在查询时也按过期展示
申请是否可发送、冷静期截止时间由后端计算，不另设数据库字段。双向去重使用 requesterId / recipientId 的 LEAST / GREATEST 表达式部分唯一索引，仅约束 PENDING 记录。

Friendship · 好友关系

一条记录代表双向好友；删除好友仅写 removedAt，保留历史。

字段 数据库类型 可空 默认值 / 约束 字段说明
id TEXT 否 主键；Prisma 生成 CUID 好友关系 ID
userLowId TEXT 否 外键 → User.id；C 排序规则下小于 userHighId 双方 ID 中较小的一方；删除用户时级联删除
userHighId TEXT 否 外键 → User.id 双方 ID 中较大的一方；删除用户时级联删除
sourceRequestId TEXT 否 唯一；外键 → FriendRequest.id 产生关系的已通过申请；删除申请时级联删除关系
createdAt TIMESTAMP(3) 否 数据库当前时间；通过时写入 建立好友关系的时间
removedAt TIMESTAMP(3) 是 NULL；非空时不能早于 createdAt NULL 表示有效好友；非空表示已删除的时间

Notification · 复用现有表

不新增业务关联字段；content 保存通知正文，type 决定跳转到收到的申请或好友列表。新增通知类型见下表。

通知类型 · NotificationType（本次新增）

值 含义 / 行为
FRIEND_REQUEST 收到新好友申请
FRIEND_ACCEPTED 自己发出的申请已通过

定位流程：先拿权限，再要位置

页面每次采集前先调用 requestAccess()：macOS 上 Chromium 不会自己申请系统定位授权（未授权时会一直等到 15 秒超时），所以由主进程通过 koffi 调用 CoreLocation 弹出系统授权框，并通过代理回调拿到用户的选择。拿到"允许"后，页面才调用 navigator.geolocation 获取经纬度，再上传坐标、解析地址。

附近搜索

检查自己开启定位 · 已上传 · 未过期
→
空间过滤ST_DWithin ≤ 1,000 米
→
筛选候选人开启定位且允许被发现
→
双方质量检查6 小时内 · 精度 ≤ 200 米
→
整理响应按距离排序
检查项 规则 结果
自己 未开启 / 无位置 / 过期 / 精度不合格 拒绝搜索并返回对应错误码
其他用户 排除自己；允许被发现；位置与精度合格 进入距离筛选
空间距离 PostGIS geography，单位米 按真实距离 + userId 排序
返回信息 用户 ID、用户名、关系/申请状态、距离档位 不返回对方经纬度
距离展示 按 50 米向上取整 例如 121 米 → 150 米
发送申请前 服务端再次检查目标是否仍在附近 避免使用过时列表直接发起申请

两组经纬度如何计算距离

输入 A 点（经度 lon₁，纬度 lat₁）与 B 点（经度 lon₂，纬度 lat₂），求两点之间的地表最短距离 d，单位为米。

计算方式：WGS 84 椭球测地线

项目通过 PostGIS 的 geography 类型在 WGS 84 椭球面上计算距离，业务代码不自行实现距离公式。

项目计算项 方式
地球模型 WGS 84 椭球：赤道半径 a = 6,378,137 米，扁率 f = 1 / 298.257223563；考虑赤道与极地方向的曲率差异
计算问题 已知两点经纬度，求椭球表面的最短测地线长度，即测地线反解问题
数据库入口 ST_Distance(pointA, pointB)；两个参数均为 geography，默认按椭球计算，返回米
坐标转换 ST_SetSRID(ST_MakePoint(longitude, latitude), 4326)::geography；先经度，后纬度
范围判断 ST_DWithin(pointA, pointB, radiusMeters)；默认筛选 1,000 米内用户，排序使用未取整的计算距离

实现依据：PostGIS 距离计算、椭球测地线反解。

计算只使用双方经纬度；地址名称和定位精度不参与距离公式。定位精度用于筛选坐标质量，距离结果表示地表距离。

好友申请与关系

A 发出申请幂等键 + 附近资格
→
PENDING仅记录申请，未成为好友
→
B 同意申请同一事务更新申请和关系
→
ACCEPTED + Friendship通知 A；双方好友列表可见

申请状态转换

接收人同意PENDING → ACCEPTED创建好友关系
接收人拒绝PENDING → REJECTED不创建关系
发起人撤回PENDING → CANCELLED不创建关系
超过 7 天PENDING → EXPIRED查询即时判定；定时任务落库

交易边界与业务规则

场景 规则
双方同时申请 复用同一条待处理申请；不会自动互相通过
重复点击 / 网络重试 双方已有待处理申请时直接返回该申请，不重复创建
同意申请 校验接收人和有效期；事务内更新状态、建立关系、写通知
通知推送 事务提交后发布事件；推送失败不回滚申请结果
删除好友 任一方可删除；设置 removedAt；原申请仍为 ACCEPTED
再次申请 仅拒绝申请后，双方冷却 24 小时；撤回、过期、删除好友不触发冷却
过期维护 每 60 秒更新过期申请
